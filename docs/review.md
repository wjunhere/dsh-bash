# Independent parity review — `dsh-bash`

Reviewed code state: the delivered implementation in this repository (code unchanged by the review; the repository was renamed to `dsh-bash` afterwards). Scope: `lib/index.js`, `lib/git-bash.js`, `index.js`, `package.json`, `cordis.patch.yml`, `test/git-bash.test.js`, `docs/verification.md`, against `docs/parity.md` and `docs/api-contract.md`, with spot checks against the installed 0.2.1-rc.2 runtime (plain copies under `B:\vibe_program\tmp\dsh-api\node_modules\@deepseek-ai\...`; cited below as `<pkg>/lib/index.js`). No plugin code, tests, docs or profile state were modified by this review. `node --check` passes; `npm test` is 10/10.

**Verdict: no blocker. One major, six minor.** The model-facing surface (tool name, description, parameters, output union, render strings, cards, prompt section) is byte-identical to the native tool; the defects are in execution-path edge semantics, structured-error metadata, and verification claims.

## Findings

| # | Severity | Location | Problem | Concrete fix |
|---|---|---|---|---|
| 1 | **major** | `lib/index.js:494-500`, `:528-531`, `:612`; contrast `:436-437` | A sandbox runner failure on the **default foreground path** (jobs registry + `promoteOnTimeout`, i.e. every foreground call in a confined composition) is not fail-closed. `startProcess` records `sandbox.runnerFailed` (494-500), but `readResult()` (528-531) returns `proc.result`; `waitOnJob` at 612 therefore returns `kind:"foreground"` with ``sandbox.runnerFailed: true`` (canonicalResult 215-224), and `renderResult` renders it as an ordinary command result. The foreground-only path in this plugin does throw (`lib/index.js:436-437`), so the two foreground paths disagree. The provider-rejection variant is also misclassified: `readResult()` rethrows the raw spawn error (514-526) instead of `SandboxUnavailableError` (`dsh-bash-sandbox/lib/index.js:114-118`). | Store the `classifyRunnerFailure` detail on `proc` and make `readResult()` reject with `new SandboxUnavailableError(sandboxFacts.mode, detail)` when it is set (and map `isRunnerSpawnFailure` in the rejection handler). Leave `processOutcome`/`sandboxNotes` untouched so background jobs keep the runner-failed marker. |
| 2 | minor | `lib/index.js:514-526`, `:127-134`, `:536-547` | A background job whose spawn is rejected by the provider reports job status `failed` with the raw error text, whereas native reports `killed` (`killed before exit`) and injects `subprocess failed before reporting an outcome: <detail>` into the job's stderr stream. Live evidence: a `run_in_background` call with a nonexistent `workdir` produced `finished [status: failed, spawn D:\software\git\Git\bin\bash.exe ENOENT]`. | 4 | minor | `lib/index.js:636` vs `:405`, `:590` | `timeoutMs` does not cover sandbox preparation. `prepareArgv` (confinement, 636) runs before any deadline is armed (405 only inside `runForeground`) and before job registration, so a slow/hung `ctx.sandbox.confine` or approval exceeds the advertised timeout and a foreground call neither promotes nor returns `[timed out after Nms]`. Cancellation still works (`exec.signal` is passed to `confine`, 391). | Arm the deadline in `execute` before `prepareArgv`, pass its signal to `confine`, thread it into `runForeground`, and on expiry use the existing `preparationTimedOut` shape for the foreground-only path / let the wait cover prep for the promote path. |

## Checked and correct

- **Tool identity/description**: name `bash` (`lib/index.js:677`); `bashDescription()` is byte-identical to `dsh-tool-bash/lib/index.js:243-245` — verified by extracting and evaluating both template literals (`$DSH_*` interpolation included), and against the live tool list exposed by the host `Tool` inspect provider.
- **Parameters**: declaration order, required flags and verbatim descriptions (`lib/index.js:679-721`) are identical to `dsh-tool-bash/lib/index.js:495-529`; live schema shows `description, command, timeoutMs, workdir, run_in_background, sandbox_permissions{enum:[workspace-write,danger-full-access]}, justification` with `required:[description,command]`. Conditional spread follows `background`/`escalationModes.length` exactly.
- **Output schema**: `oneOf` order background → promoted → foreground; required/optional sets, `additionalProperties:false`, stdout/stderr `{text,truncated,spillPath?}`, sandbox `{mode,denied,enforcement?,runnerFailed?}`, `stopped` optional (`lib/index.js:229-282`, `:722-741`) match `dsh-tool-bash/lib/index.js:325-648` field for field and order for order.
- **`render()`**: marker set and order (`[sandbox: …]`, escalation hint, `[timed out after Nms]`, `[stopped: …]`, `[killed by signal: X]` else `[exit code: N]`), `(no output)`, `[stderr]`, truncation notice, `started background job <id>`, promoted text (`lib/index.js:60-113`, `:742-750`) match `dsh-tool-bash/lib/index.js:135-207`; a decoded-literal diff found no native model-facing string missing from the plugin except the composition-guard text and the unreachable prep-timeout token (see below).
- **Cards**: `presentCall`/`presentResult`/`presentationMeta` (`lib/index.js:159-188`, `:750-754`) are line-for-line equivalents of `dsh-tool-bash/lib/index.js:246-287`, `:653`, including the console-fenced generic card and `parseExitStatus` pill extraction.
- **systemPrompt**: `name:"tool:bash"`, `getSectionOrder("TOOL_BASH")` (=1000), and the exact text (`lib/index.js:665-669`) match `dsh-tool-bash/lib/index.js:376-380` and `dsh-system-prompt/lib/index.js:17`.
- **Validation**: the three error strings, the same-mode escalation short-circuit and the `justification` normalisation (`lib/index.js:146-153`) are identical to `dsh-tool-bash/lib/index.js:235-242`.
- **Abort shape**: `HarnessError("tool call aborted", TOOL_ABORTED)` with `name="AbortError"` (`lib/index.js:136-140`) matches `dsh-tool-bash/lib/index.js:319-323` (metadata caveat in finding 3).
- **Job contract**: `kind:"bash"`, `label:args.command`, `toolCall:{callId,rootCallId}`, `owner:exec.agent.id` (`lib/index.js:553-558`) match `dsh-tool-bash/lib/index.js:393-402`; `start/read/wait/kill/remove` signatures and `caller=agent.id` match `dsh-jobs-local/lib/index.js:412-527`; pull sources use non-consuming `readFrom(offset)` (`lib/index.js:536-547`); normal-vs-killed outcome vocabulary (`:127-134`) matches `dsh-tool-bash/lib/index.js:42-55`.
- **`promoteOnTimeout` mechanics**: job registered before the process starts (`:550-576`), job process spawned without an executor deadline (`:461-462`), `wait(id, timeoutMs, owner, exec.signal)` (`:590`), one consuming `read` (`:599`), `kind:"promoted"` (`:601-607`), job left alive; settled path removes the job then reads the process (`:609-614`); abort path kills + waits + conditional remove. The native "timed out during preparation" branch (`dsh-tool-bash/lib/index.js:447-470`) is intentionally absent because this plugin spawns synchronously inside `jobs.start`'s `run()` (`dsh-jobs-local/lib/index.js:439`), so `attached.process()` is always defined — checked and not a defect.
- **Sandbox seam**: `confine` is awaited and receives the policy and a signal (`lib/index.js:386-401`), facts are captured from the provider result, danger-full-access short-circuits to `{mode, denied:false}`; a confined policy with no `ctx.sandbox` throws (fail-closed); classification uses the exported `classifyRunnerFailure`/`matchesSignature`/`isRunnerSpawnFailure` (`:8-12`, `:416`, `:436-442`) rather than local copies.
- **cwd/env**: relative `workdir` uses the native string concat `${sessionCwd}${sep}${workdir}` (`lib/index.js:191-196`) via `ctx.workingDirectory.ensure(agent, signal)` and `defaultDirectory` (`:625-626`, service fields verified in `dsh-working-directory/lib/index.js:18-28,87-104`); `NO_COLOR/TERM/PAGER/GIT_PAGER` are applied before `ctx.shellEnv.collect(exec)` (`:53`, `:349-353`, `:627`), matching `dsh-bash-local/lib/index.js:22-27,122-126`.
- **Submission**: `subprocess.spawn` request shape matches the shipped `spawnSpec` (`lib/index.js:337-355` vs `dsh-bash-local/lib/index.js:107-128`): same collect/spill budgets, `graceMs`, `stdin:"ignore"`, `cwd`, env order; `finalOutput` is the same `readFrom(0)` + `lossy→truncated` projection (`lib/index.js:357-365` vs `dsh-bash-local/lib/index.js:33-40`, `dsh-subprocess-local/lib/output.js:188-198`).
- **Registration**: initial registration then rebuild on `ctx.inject(['jobs'])` and `ctx.inject(['sandboxPolicy','sandbox'])` with effect cleanup (`lib/index.js:758-775`) is the shipped idiom (`dsh-tool-bash/lib/index.js:715-728`); `ctx.fiber.state === 2` = loaded (finding 7), so recovery only runs while active.
- **Live spot checks through this plugin's own `bash` tool**: `$DSH_PROFILE/$DSH_SESSION_ID` present, `TERM=dumb NO_COLOR=1 PAGER=cat`; `exit 7` renders `[stderr]` + `[exit code: 7]`; a 1060 ms timeout produced the exact promoted text and the job finished later with a completion notice; invalid `workdir` yields `Error: spawn D:\software\git\Git\bin\bash.exe ENOENT`. `npm test` 10/10 matches `docs/verification.md:28` (unit tests cover discovery only, as documented).
- **Not live-testable here / stated limits**: sandbox denial and escalation were not exercised (profile default is `danger-full-access`), matching `docs/verification.md:32`; the client toolview claim could not be reproduced (finding 6); the abort path is code-reviewed only.
